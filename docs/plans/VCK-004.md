## Understanding
`contracts/` holds `openapi.yaml` (3.1, 32 operations, custom routes only), four event JSON Schemas, ten fixtures and
`vnpay/generate_vectors.py` + `golden-vectors.json`. This story adds the tooling around them: lint, schema compile, vector
regeneration, breaking-change gate, generated storefront/backend artefacts, and the "generated output is committed and never
drifts" gate. Root CLAUDE.md §9: **no edit of `contracts/` content in a feature branch**; every new file lives outside it.

## Rulings
- **R-004-1** New files live in `tools/contracts/` (workspace `@vck/contracts-tools`), a root `.spectral.yaml` and `.github/workflows/contracts.yml`
  (separate from VCK-003's `ci.yml`, so parallel branches never conflict). If Spectral reports errors on the CURRENT `openapi.yaml`,
  do not edit it: tune the ruleset only for rules the docs/04 conventions do not require, and write the rest as a Ruling + a follow-up `contract/` PR.
- **R-004-2** Tools (confirm current CLI/API via Context7 before use): `@stoplight/spectral-cli`, `ajv` + `ajv-formats` (draft 2020-12), `openapi-typescript` (storefront types),
  `orval` in `zod` mode (backend validators), oasdiff (Go binary; CI installs a pinned release with a verified checksum). MSW handlers come from a small in-repo script
  (orval's MSW mode fabricates faker data; the AC wants the fixtures). Scripts are plain `.mjs` (Node 20 cannot run `.ts` directly). Every dependency is noted in the PR.
- **R-004-3** Fixture → operation mapping is explicit: `tools/contracts/fixture-map.json` (`operationId` → `{ fixture, status }`); operations without a fixture get no handler and are listed in the output header. A test fails if a mapped fixture or operationId does not exist.
- **R-004-4** Generated output is committed under `apps/storefront/src/generated/` and `apps/backend/src/generated/` (AC3, lane crossing sanctioned by the story), starts with a `GENERATED — DO NOT EDIT` header, is ignored by ESLint and Read-denied already (`**/generated/**`).
  To typecheck it, PLAT adds only `msw` (storefront devDependency) and `zod` (backend dependency) to the stub `package.json`s; VCK-005/006 own everything else there.
- **R-004-5** oasdiff gate: workflow compares the PR's `openapi.yaml` to `origin/main`; a breaking result passes only when the PR has label `contract-breaking` AND the body links `docs/adr/ADR-<nnn>`. The decision logic is a pure function with unit tests; the workflow feeds it oasdiff's JSON, labels and body via `env:` (no shell interpolation of PR text).
- **R-004-6** Python 3 is required for the vectors (`python3 contracts/vnpay/generate_vectors.py`); CI runners have it, `make contracts` fails with a clear message if it is missing.
- **R-004-7** The lockfile will conflict with VCK-003's `yaml` dependency: whichever PR merges second rebases and regenerates `pnpm-lock.yaml`.
