## Rulings
- **R-008-1** Workspace `tools/docs/` (`check.mjs`, `release.mjs`, `lib/*.mjs`, `test/*.test.mjs`); `test` script `node --test test/*.test.mjs` so turbo/CI `checks` runs it. Zero new dependencies: Node stdlib only (`yaml` is already a root devDependency if front-matter is ever needed; not needed now).
- **R-008-2** Changesets: NO `@changesets/cli`. `release.mjs` reads `.changeset/*.md` (excluding README.md) with a 20-line parser: front-matter lines `"pkg": patch|minor|major`, body = summary. Reason: 2-pt story, no versioning/publish flow is used (the repo is not published to npm), a dependency adds lockfile churn and Node-version risk. A missing `.changeset/` dir is valid (zero changesets). A malformed changeset file (no front-matter, bad bump, empty body) FAILS. Ceiling: no bump computation; add the real CLI only if packages are published.
- **R-008-3** `docs-check` scope now (docs/12 §6 subset): (a) BUG files, (b) PROGRESS "Now" ≤ 15, (c) RELEASE files have every template section, (d) required files exist (`docs/bugs/README.md`, `docs/releases/README.md`, `docs/progress/PROGRESS.md`, `CHANGELOG.md`, both templates), (e) BUG index rows in `docs/bugs/README.md` and RELEASE index rows match files on disk. DEFERRED (follow-up in PROGRESS): dead-link check, story-id existence, ADR link resolution, YAML/JSON parse. The Makefile comment in CLAUDE.md §3 stays true for what ships; the PR updates it to list the shipped scope.
- **R-008-4** BUG validation (AC1): files matched by `docs/bugs/BUG-[0-9][0-9][0-9]-*.md`; `BUG-000-template.md` is skipped by exact name; any other `BUG-*.md` with a non-matching name FAILS. Required on every bug: `Severity: S1..S4` and `Status:` one of OPEN|INVESTIGATING|FIXED|VERIFIED|CLOSED on the header line (exact regexes from the template). When status is FIXED, VERIFIED or CLOSED: `## Root cause` section non-empty (not just `1. Why ...`), `## Regression test` section contains a token matching `\[BUG-<nnn>\]` with the file's own number. OPEN/INVESTIGATING need no root cause. Headings matched exactly (`## Root cause (5 whys)`).
- **R-008-5** "Now" block (AC3): lines from the line after `## Now` up to (excluding) the next line starting `## `; trailing and leading blank lines are trimmed, interior blank lines count, every other line counts (a wrapped bullet is a line). Limit 15. Missing `## Now` heading, missing file or an empty block FAILS. Two `## Now` headings FAIL.
- **R-008-6** `make release VERSION=x.y.z` (AC2) = draft only, never commit/tag/push. Steps, all fail-closed: `VERSION` matches `^\d+\.\d+\.\d+$`; git tree clean (`git status --porcelain` non-empty FAILS; a git error FAILS); `docs/releases/RELEASE-<v>.md` must not exist (idempotent refusal); `CHANGELOG.md` must not already contain `## [<v>]`; last tag = `git describe --tags --abbrev=0 --match 'v*'`; with NO tag the range is the whole history (first release) and this is stated in the output; `git log` errors or an empty range with zero changesets FAIL ("nothing to release"). Clock injectable via `VCK_DATE` (yyyy-mm-dd, validated), repo root via `VCK_ROOT` (default: two dirs above the script, via `fileURLToPath`). Writes the RELEASE file (template with sections filled where derivable, rest left as the template's own prompt text for the tech lead, as docs/12 §4 says) and prepends to CHANGELOG under `## [Unreleased]`-preserving order: new `## [x.y.z] - date` block is inserted directly after the `## [Unreleased]` block's end (before the first existing `## [`), linking the RELEASE file. Both files are written only after all inputs parsed (no partial write).
- **R-008-7** Commit parsing: `^(feat|fix|refactor|docs|test|chore|perf|ci)(\((scope)\))?(!)?: (.+)$` on subjects; `VCK-\d{3}` taken from a trailing `(VCK-nnn)`; `BREAKING CHANGE:` footer also marks breaking. Non-conforming subjects are listed under a "Non-conforming commits" line in the output and the draft (never silently dropped); merge-commit subjects (`Merge `) and `(#nn)` suffixes are tolerated. Mapping: feat → Features table (Story, Title, Flag = `—`); fix → Bugs fixed (BUG ids from `BUG-nnn` in subject/body, else `—`); breaking → Summary line "BREAKING:"; perf/refactor/ci/chore/docs/test → CHANGELOG `Changed`/`Fixed`/`Added` only (feat → Added, fix → Fixed, others → Changed, docs/test/chore/ci omitted from CHANGELOG but counted in the output).
- **R-008-8** CI: add ONE step to the existing `checks` job in ci.yml after the install step: `run: node tools/docs/check.mjs` (name "Docs check"). Safe under the guards: job ids unchanged (scripts/ci.test.mjs pins {checks, integration, pins, security}), no `${{`, no job-level `if`. A new guard `scripts/docs-ci.test.mjs` (scripts/ci.test.mjs is at 294/300 lines) asserts the step exists, is not `continue-on-error`, has no `|| true`. No new workflow file, so no concurrency-prefix work.

Change the minimum: turn that one line into links to docs/12 §1 and list the DoD doc items as sub-bullets with repo-relative links (contracts, docs/05 data model, docs/adr, docs/progress/PROGRESS.md, docs/bugs, docs/releases) and add `make docs-check` green to the verification line. ## Risks
- Regex-based Markdown parsing is brittle if templates change: headings are asserted against the real templates in a test (template file passes its own structural check).
- Merged PR subjects end `(#n)`: handled by R-008-7; squash merges make the commit subject the source of truth.
- `git describe` needs tags fetched: CI does not run `make release`; locally documented in the script's error text.
- docs-check in `checks` runs for every PR (not only docs PRs): cost under 1 s, no install beyond the existing one.
- Changesets dir absent today: release relies on commits alone until a story adds changeset files; covered by the "dir absent ok" test.
