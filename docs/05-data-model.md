## 1. Ownership
| Store | Owner | Migration tool | Location |
| --- | --- | --- | --- |
| Postgres — Medusa core modules | Medusa (upgrade PRs only) | `medusa db:migrate` | node_modules (read-only) |
| Postgres — app custom modules | BE | `medusa db:generate <module>` | `apps/backend/src/modules/*/migrations` |
| Postgres — plugin modules | PKG (per plugin) | plugin migrations | `packages/*/src/modules/*/migrations` |
| Module links | BE | generated by `db:migrate` from `src/links` | link tables |

| Redis | runtime only | — | no durable data |
| Object storage | File module | — | `products/`, `reviews/`, `slips/`, `feeds/` |

| audit_log (BE) | `audit_log` | admin mutations | append-only (no UPDATE/DELETE grant for app role) |

Module links (`src/links`): order↔payment_reconciliation, fulfillment↔shipment, product↔review, customer↔review,
customer↔wishlist_item, cart↔transfer_instruction, order↔guest_access_event.
Ephemeral guest-access state (tokens, rate counters, OTP challenges) lives in Redis with TTL only (docs/14 §6).

## 3. Modeling rules
- Money: `bigNumber`/bigint columns holding integer VND; no numeric with scale; conversion helpers in `src/lib/money.ts`.
- Statuses: text + CHECK constraint (DML enum) mirroring OpenAPI enums; transitions enforced in code by a state table.
- Time: `timestamptz` (UTC); business dates computed with Asia/Ho_Chi_Minh.
- IDs: Medusa prefixed ids (`recon_`, `shp_`, `rev_`…); provider ids stored as text, never as PK.
- PII: only in Medusa customer/address tables; custom tables reference `customer_id`; `provider_event.payload` stored
  redacted (no names/phones/bank account numbers) and truncated to 8 KB.
- Soft delete only where Medusa already does; audit_log never deleted; provider_event retained 400 days then purged.
- Naming: snake_case, singular table names, index names `idx_<table>_<cols>`.

## 5. Migration rules
Forward-only; generated from DML, reviewed in PR; expand → migrate → contract for renames (3 PRs); data backfills as
scripts in `tools/` with dry-run; no destructive migration in the same release that stops using a column; migration
names reserved in the plan (`Migration<yyyymmddhhmm>`).

## 6. Key queries and indexes
| Query | Index |
| --- | --- |
| Recon sweep: status = PENDING_QUERY and created_at < now()-15m | `idx_payment_reconciliation_status_created_at` (partial on PENDING_QUERY) |
| IPN lookup by txn_ref | unique `txn_ref` |
| Dedupe provider events | unique (`provider`, `provider_event_key`) |
| VietQR match by memo | unique `memo` |
| Tracking by order | link table index on order_id + `idx_shipment_event_shipment_id_occurred_at` |
| Reviews by product (approved, newest) | `idx_review_product_id_status_created_at` |
| Wishlist by customer | unique (`customer_id`, `variant_id`) |
| KPI by day | read-model `mv_daily_sales` (materialised view refreshed every 15 min) — ADR required if expanded |
| Audit by actor/entity | `idx_audit_log_actor_id_at`, `idx_audit_log_entity_entity_id_at` |
New hot queries require `EXPLAIN (ANALYZE, BUFFERS)` output against the realistic seed in the PR.
