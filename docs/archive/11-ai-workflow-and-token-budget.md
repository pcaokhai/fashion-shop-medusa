# AI Workflow and Token Budget
Version 1.0 · 2026-09-29 · Owner: Tech lead

Context is a budget. Every token loaded is paid on every following turn of the session. Rules below keep lane
sessions fast, cheap and accurate. They are MUST unless marked SHOULD.

## 1. Principles
1. **Load late, load little**: find first (`rg -n`), then read only the needed range.
2. **Files are memory, chat is not**: decisions go to plans/ADR/PROGRESS; a new session reads files, never old chat.
3. **One story, one session**: `/clear` after `finishing-a-development-branch`; start the next story fresh.
4. **Summaries up, details down**: subagents return short summaries; details stay in files they wrote.
5. **Deterministic work is scripted**: vectors, codegen, release notes, seeds are scripts — never generated by the model in chat.

## 2. What never enters context
Enforced by `.claude/settings.json` deny rules and `.gitignore`:
`node_modules/`, `.medusa/`, `.next/`, `dist/`, `coverage/`, `playwright-report/`, `**/generated/**` (read the
contract instead), `pnpm-lock.yaml`, `tools/seed/out/`, `*.dump`, `*.sql.gz`, `.env*` (only `.env.example`), large
fixtures > 200 KB, `.claude/skills/ui-ux-pro-max/data/**` (query it through `search.py`, docs/13 §1.2). `docs/assets/*.sql` only when a story touches that DDL.

## 3. Reading and command-output rules
| Situation | Do | Don't |
| --- | --- | --- |
| Find a story | `rg -n "^### VCK-203" docs/06-user-stories.md` then read ~25 lines | read the whole stories doc |
| Find a doc section | `rg -n "^## |^### " docs/02-*.md` then read the section range | read whole docs "for context" |
| Find code | `rg -l` → `rg -n` → read ranges | open whole directories |
| Re-check a file | trust your last read unless you or a tool changed it | re-read unchanged files |
| Run tests | targeted: `pnpm --filter <pkg> test -- -t "VCK-203-AC2"` | full suite on every edit |
| Noisy commands | `… 2>&1 | tail -n 40`; reporters `--reporter=dot`/`--silent`; `turbo --output-logs=errors-only` | paste full logs |
| Failures | re-run only the failing target with more detail | re-run everything |
| Big diffs | `git diff --stat` then targeted `git diff -- <file>` | dump the full diff |
| Generated types | read `contracts/openapi.yaml` path section | read generated output |

## 4. Session lifecycle
1. Start: root CLAUDE.md (auto) → lane CLAUDE.md → PROGRESS "Now" block (≤ 15 lines) → story block → cited sections.
2. Plan (`writing-plans`): ≤ 120 lines; tasks reference files and test names; code snippets only where the
   interface is non-obvious (≤ 20 lines each).
3. Execute: `subagent-driven-development`; the main session holds the plan and review notes, not the code.
4. At ~60% context: `/compact` with focus: "keep plan path, current task number, failing test names, rulings".
5. End: append PROGRESS entry (≤ 8 lines), then `/clear`.
Handoff between sessions = plan file + PROGRESS entry. Never ask a new session to "read the previous chat".

## 5. Skills and subagents
- **brainstorming**: only when the story leaves a design decision open (DoR says so); otherwise skip it.
- **writing-plans**: compact plans (§4.2); link doc sections instead of copying them.
- **Subagent brief** (≤ 15 lines): task · files it may edit · failing test to write first · verification command ·
  return format "≤ 10 lines: result, files changed, test output tail, open questions".
- **Project subagents** in `.claude/agents/`:
  - `test-runner` (small/fast model): runs the given command, returns only failing test names + first error lines.
  - `doc-keeper` (small/fast model): updates PROGRESS/BUG/RELEASE/CHANGELOG from a structured brief.
  Use them for mechanical work so the main session keeps its context for reasoning.
- **dispatching-parallel-agents**: only for disjoint file sets; each agent gets its own brief; no shared scratch files.
- **requesting-code-review**: pass the diff stat, plan path and AC list — not the whole conversation.

## 6. Writing project skills (SHOULD, when Khai adds custom skills)
- `description` says exactly when to trigger and when not to, so skills don't load on unrelated tasks.
- `SKILL.md` ≤ ~300 lines; move reference material to `references/` read on demand (progressive disclosure).
- Put deterministic steps in `scripts/` and call them; the model should not re-derive what a script can compute.
- Don't duplicate CLAUDE.md or docs content; point to paths and sections.
- Keep examples short and representative; one good example beats five similar ones.

## 7. Documentation style for token efficiency
Tables over prose; IDs over repetition (`see ADR-007` not a re-explanation); one source of truth per fact
(contracts > docs); section headings stable so `rg` anchors work; no screenshots of text; keep each doc ≤ ~600 lines
(split otherwise, keep numbering).

## 8. Measuring
Record tokens/cost per story in the PROGRESS entry (from the session usage display). Targets (SHOULD): ≤ 3 pts
story within one session without `/compact`; 5–8 pts story ≤ 2 compactions. Retro reviews the three most expensive
stories and adds a rule here if a pattern repeats.
